# 검증 상태와 Windows 확인 절차

최신 검증: [2026-11-05 사용자 PC 로컬 검토 및 검증](LOCAL_VALIDATION_20261105_KO.md). Windows에서 테스트·빌드·publish를 완료했다. 아래 Linux 결과는 이전 기록이며, UI 및 OS 통합 확인 목록은 계속 유효하다.

2026-11-05. Linux 클라우드에서 수행한 검증:

- WPF Release 빌드 성공, 경고 0 / 오류 0.
- 핵심 클릭 정책 12개 시나리오 통과: 실행 없음, 뒤의 앱 활성화, 선택 창 최소화, 전체 최소화, 전체 복원, 단일 창 왕복, 문맥 초기화, 다른 앱 전환.
- win-x64 self-contained publish 성공. PE32+ x86-64 Windows GUI 실행 파일 생성.
- 소스/문서/실행 파일 ZIP 및 체크섬 생성.

위 테스트는 순수 클릭 정책에 한한다. Windows 실행 환경이 없어 Win32/COM/DWM 결과, UI 캡처, 실제 로그인·대화 연동, 성능 측정은 수행하지 않았다. 사용자 PC를 현재 클라우드 도구로 원격 제어했다고 주장하지 않는다.

## Windows에서 다음으로 실행할 확인

1. 새 독 실행 전/후 기본 작업 표시줄, 숨겨진 트레이 아이콘, 네트워크·소리·시계 접근을 비교한다. 종료 후 기본 Windows 동작이 유지되는지 확인한다.
2. 메모장과 탐색기를 각 두 창 연다. 앱별 하나의 아이콘과 개수 표시, 전경/배경 선택을 확인한다.
3. 전경 앱 아이콘을 한 번 누르면 선택 창만 최소화되는지, 4초 이내 다시 누르면 나머지도 최소화되는지, 다시 누르면 모두 복원되는지 확인한다. 창 하나만 있을 때도 왕복한다.
4. 다른 앱 선택·개별 미리보기 선택·가상 데스크톱 변경 후 이전 전체 최소화 상태가 남지 않는지 확인한다.
5. 실제 사용하는 트레이 앱에서 일반 최소화 → 트레이 숨김 → 트레이에서 복원을 수행한다. 일반 최소화 중 아이콘 유지, 트레이 전용 중 제외, 외부 복원 때 자동 복귀·중복 창 없음 여부를 각각 기록한다. 고정/비고정 모두 확인한다.
6. 앱 우클릭의 정상 닫기 요청에서 저장하지 않은 문서의 저장 질문이 뜨는지 확인한다. 강제 종료를 사용하지 않는다.
7. 미리보기에서 창 제목으로 최소화 창을 선택한다. 썸네일 미지원/보호/최소화 창에서도 제목 선택이 가능한지 확인한다. 미리보기를 닫은 뒤 자원이 해제되는지 확인한다.
8. Win+Tab으로 실제 Windows 가상 데스크톱 두 곳에서 같은 앱 창을 연다. 현재 공간의 창만 조작하는지, 앱 실행이 현재 공간을 유지하는지 확인한다. 독의 작업 보기 호출 결과도 확인한다.
9. 손잡이로 4개 끝에 놓고 세로 독의 AI가 화면 안쪽으로 펼쳐지는지 확인한다. 기본 표시줄과 겹치지 않는지 확인한다.
10. 100%/150% 배율 모니터 사이 이동, 주 모니터 변경, 선택 모니터 분리, 해상도 변경을 시험한다. 독이 하나만 표시되고 남은 화면 안으로 돌아오는지 확인한다.
11. 자동 숨김 때 아래 앱을 클릭할 수 있는지, 작업영역 끝에 커서를 놓아 다시 나타나는지 확인한다. Windows 기본 표시줄 자동 숨김이 켜진 조합도 별도로 확인한다.
12. 아이콘 순서/고정/서비스 선택/서비스별 초안을 변경하고 종료·재시작한다. 영속성을 확인한다. AI의 조회·새 대화·전송 버튼이 계속 비활성이고 네트워크 요청이 없는지 확인한다.
13. 앱 20/40개에서 한 줄/한 열 길이와 작업영역 픽셀을 기록한다. 초과 정책은 별도 결정하며 줄바꿈이나 자동 축소를 추가하지 않는다.
14. 작업 관리자에서 독 닫힘/열림, AI 접힘/펼침, 미리보기 유무별 CPU·메모리와 클릭 지연을 측정한다. 목표값을 임의로 통과 처리하지 않는다.

로그 경로: `%LOCALAPPDATA%\GlassDock\errors.log`. 비정상 상태면 Windows 기본 트레이 메뉴에서 독을 종료한다. 이 프로그램은 시스템 표시줄 설정, 단축키, 레지스트리 시작 항목을 변경하지 않는다.
