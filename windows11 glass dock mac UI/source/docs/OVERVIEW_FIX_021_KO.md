# 0.2.1 전체 창 보기와 창 선택 수정

사용자 화면에서 전체 창 보기 버튼은 가운데 제목 표시줄이 있는 진단용 창을 열고, 큰 썸네일 하나와 제목/미리보기 버튼 목록을 표시했다. 승인된 전체 창 선택 화면으로 구현하지 못했던 부분이다.

수정 사항:
- 전체 창 보기 버튼은 선택한 모니터의 Windows 작업영역을 채우는 제목 표시줄 없는 선택 화면을 연다. 현재 작업공간의 창을 각각 실제 DWM 썸네일 카드로 표시한다.
- 카드의 썸네일 영역과 제목 모두 같은 선택 버튼이다. 선택 시 선택 화면을 먼저 닫고 WPF의 닫기/포커스 처리가 끝난 뒤 원래 앱 창을 활성화한다.
- 최소화 창은 비동기 복원을 요청하고 최소화 상태가 해제됐는지 최대 600ms 확인한 뒤 활성화한다. 창이 닫혔거나 다른 공간으로 이동했으면 조작하지 않는다. Windows의 전경 전환 거부는 우회하지 않는다.
- Esc, 빈 배경 클릭, 닫기 버튼으로 선택을 취소하며 원래 창을 새로 실행하지 않는다. Tab/Enter로 카드를 선택할 수 있다.
- 앱 우클릭 미리보기도 같은 카드 선택 UI를 사용한다. 전체 창 보기는 화면 전체, 앱 미리보기는 작은 선택 패널이다.
- 원본 창의 비율을 유지하며 모니터 배율을 반영한 물리 클라이언트 좌표에 DWM 썸네일을 배치한다. 모니터 변경 때 선택 화면을 닫고 자원을 해제한다.
- 같은 선택 창을 여러 개 만들지 않으며 닫힐 때 모든 DWM 썸네일과 갱신 타이머를 해제한다. 일반 앱 창의 위치·크기는 바꾸지 않는다.

Windows 작업 표시줄과 트레이는 유지한다. 화면 선택 UI는 Windows 창을 직접 이동/축소시키는 시스템 애니메이션 대체가 아니라 실제 창을 선택하는 오버레이다. 다른 가상 데스크톱의 창은 포함하지 않는다. 최소화/보호된 창의 썸네일 제공 여부는 Windows와 해당 앱에 따라 다르며 제목 선택은 유지한다.

검증: Release WPF 빌드, 클릭 정책 12개 시나리오 및 전체 창 타일 배치/비율 보존 28개 시나리오. 독은 저장한 앱 아이콘 순서를 OS의 현재 창 열거 순서로 덮어쓰지 않는다. 사용자 PC에서 창 여러 개와 최소화 창의 선택, Esc 취소, 원래 창 수 유지, 작업 표시줄 보존을 확인해야 한다.

이 대화는 여전히 클라우드 작업 환경이다. 사용자 Windows PC의 로컬 소스에 자동 반영되지 않는다. 소스 수정 ZIP의 Apply-Source-Fix.cmd를 실행해 VS Code의 소스 폴더를 선택하면 해당 소스에만 수정본을 적용한다. 기존 0.2 파일과 체크섬이 일치할 때만 적용하고 원본을 백업한다. 로컬 변경이 있으면 덮어쓰지 않는다. 실행 중인 독은 사용자가 먼저 종료하고 소스를 다시 실행한다.
