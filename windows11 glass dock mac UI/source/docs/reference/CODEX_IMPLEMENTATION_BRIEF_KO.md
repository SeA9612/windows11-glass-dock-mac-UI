# Windows 개인용 독 — 실제 프로그램 제작 인계서

기준일: 2026-11-05. 최신 승인 미리보기: **수정본 14** (`START-HERE.html`, 원본 파일명 `tray-sync-preview-v14.html`).

## 1. 이 문서를 읽는 Codex에게

사용자는 브라우저 체험 화면 제작을 마치고 실제 Windows 프로그램을 만들려고 한다. 먼저 이 문서와 최신 미리보기, 관련 원본을 읽고 실제 실행 가능한 프로그램으로 옮겨라. 기존 HTML을 다시 보여주는 것만으로 작업을 완료했다고 하지 말 것.

현재 저장소·기술 스택·설치 방식은 확정되지 않았다. 작업 환경을 확인하고 선택 이유를 짧게 설명한 뒤 구현을 진행한다. 아래에서 ‘확정’한 제품 동작은 유지하되, 미리보기 코드의 구현 구조까지 그대로 이식할 필요는 없다. 일반적인 가역적 구현 선택은 매번 확인을 요구하지 않는다. AI 연결 등 실현 가능성이 미확인인 부분은 검증 결과와 남은 제약을 분명히 보고한다.

우선순위: **이 문서의 최신 요구사항 → 최신 v14 화면 → 대화의 최근 사용자 결정 → 이전 버전 자료**. 옛 답변의 추측이나 폐기된 기능을 최종 요구로 되살리지 않는다.

## 2. 사용자가 만들려는 것과 범위

개인적으로 사용할 Windows용 독 및 창 전환 인터페이스다. macOS에서 느낀 자연스러운 모션과 시각적 사용감을 원한다. Windows를 다른 운영체제로 교체하려는 목적은 아니다.

- 파일 탐색기, Chrome 등 프로그램 내부 화면·기능·창 버튼은 Windows 기본을 유지한다.
- 기존 키보드 입력과 단축키를 임의로 바꾸지 않는다. 전역 단축키를 가로채거나 재배치하는 것이 목표가 아니다.
- 새로 만드는 부분은 독, 창 미리보기, 앱/창 선택 화면, 전체 창 보기, 작업공간 전환, 관련 모션, 독 안의 AI 대화 영역이다.
- 현재 HTML 속 탐색기·Chrome·메모는 디자인 확인용 가짜 창이다. 실제 제품에서 해당 프로그램들을 재구현하지 않는다.
- 개인용이며 출시·스토어 배포·서버 운영은 아직 요청하지 않았다.

## 3. 승인된 외형과 모션

- 밝은 반투명 유리 느낌의 독을 유지한다. 검은 다이내믹 아일랜드 외형은 사용자가 거절했다.
- 독 안의 AI 영역이 부드럽게 펼쳐지고 접히는 구조를 유지한다.
- 앱 진입·최소화·복원·미리보기·창 선택·작업공간 전환의 자연스러운 움직임이 핵심이다.
- 미리보기의 전환 시간 시작값은 480ms이며 조정 가능하다. 실제 프로그램에서의 성능과 입력 지연을 측정하며 다듬는다.
- macOS 코드를 가져오거나 시스템 창 애니메이션을 임의의 방식으로 완벽하게 대체할 수 있다고 가정하지 않는다. 독 자체 모션과 실제 앱 창 모션을 나누어 구현 가능한 범위를 확인한다.
- 미리보기 링크는 별도로 제공하고 채팅 안에 자동 삽입하지 않는다. 사용자는 인라인 체험 화면 이후 캡처가 안 되는 문제를 경험했다.

## 4. 독 아이콘과 실행 앱

### 표시·고정·순서

- 일반 창이 있는 실행 앱을 자동 감지해 독에 추가한다. 같은 앱의 여러 창은 아이콘 하나로 묶는다.
- 고정 앱은 실행 전과 종료 후에도 남고, 비고정 앱은 마지막 일반 창이 닫히면 제거한다.
- 실행 표시 점과 여러 창의 개수 배지를 표시한다.
- 드래그로 아이콘 순서를 바꾸고 고정할 수 있다. 미리보기 메뉴에서도 고정/해제를 제공한다.
- **최종 결정은 모든 아이콘을 한 줄로 길게 보여주는 것**이다. 페이지 넘김, 접기/펼치기, 두 줄 줄바꿈은 폐기했다. 기존 디자인의 아이콘 크기를 유지한다.
- 가로 가장자리에서는 한 줄, 좌우 가장자리에서는 한 열로 배치한다.
- 실제 배치는 선택한 모니터의 유효 작업영역·해상도·화면 배율을 기준으로 한다. HTML의 최소 폭 720px은 체험용일 뿐 실제 화면 규격이 아니다.
- 매우 많은 앱으로 물리적인 화면 길이를 초과하는 극단적인 경우의 정책은 아직 합의하지 않았다. 임의로 페이지 넘김·두 줄·무제한 축소를 되살리지 말고 실제 측정 결과를 제시해 결정한다.

### 같은 앱 아이콘의 클릭 규칙

대상은 현재 작업공간의 해당 앱 창들이다.

1. 실행 중인 대상 창이 없으면 현재 작업공간에서 앱을 실행한다.
2. 해당 앱이 뒤에 있으면 선택 대상 창을 앞으로 가져온다.
3. 앞에 있는 앱 아이콘을 누르면 현재 선택한 창 하나만 최소화한다.
4. 같은 앱을 이어서 다시 누르면 나머지를 포함해 해당 앱의 모든 창을 최소화한다.
5. 해당 앱의 모든 창이 최소화돼 있으면 다시 누를 때 **모든 창을 함께 복원**한다.
6. 미리보기·전체 창 보기에서 개별 창을 선택하면 그 창을 복원하고 활성화한다.

다른 앱 선택·작업공간 변경 등 문맥이 바뀌면 ‘다음 클릭은 모두 최소화’ 같은 임시 상태를 정리한다. 한 창만 있는 경우에도 자연스럽게 최소화/복원이 왕복해야 한다. 다른 작업공간의 창을 함께 최소화하지 않는다.

### 미리보기

- 실제 열린 창의 썸네일과 제목을 보여주고 창별로 선택할 수 있어야 한다.
- 창 선택, 새 창, 고정/해제, 앱 종료 기능이 미리보기에서 확인되어 있다.
- 최소화된 창의 미리보기를 위해 앱을 모두 강제로 상시 렌더링하지 않는다. 운영체제가 제공하는 기능 또는 필요 시 갱신하는 방식을 검토한다.
- ‘새 창’은 앱마다 지원이 다르므로 앱별 실행 처리를 확인한다. ‘종료’ 때문에 강제 프로세스 종료나 데이터 손실을 기본 동작으로 넣지 않는다.

## 5. 트레이와 Windows 기본 작업 표시줄

사용자는 Windows 오른쪽 트레이에서 숨겨진 앱 아이콘을 펼쳐 보고 네트워크·소리·시계 등에 접근하는 편의성을 중요하게 여긴다.

- **Windows 기본 작업 표시줄과 트레이를 유지하는 것을 초기 구현 기준으로 한다.** 제거·대체는 승인되지 않았다. 기본 작업 표시줄과 새 독이 겹치지 않게 배치한다.
- 사용자 발언은 ‘윈도우 기본을 따르는지, 기본 하단바를 없애는지’ 질문이었고, 기존 답변에서는 기본 표시줄을 유지하는 방향을 제안했다. 이후 숨기기/삭제에 대한 승인은 없으므로 이 문서는 보존을 기본값으로 삼는다.
- 트레이에만 상주하고 일반 창이 없는 앱은 독에서 제외한다. 고정했더라도 트레이 전용 상태에서는 숨기는 것이 현재 미리보기 동작이다.
- **일반 최소화와 트레이 전용 상태를 구분**한다. 최소화만 했다고 독에서 없애면 안 된다.
- 트레이 아이콘을 클릭하거나 다른 경로로 일반 창이 다시 나타나면 **독에 자동으로 복귀**해야 한다. 독의 특별한 ‘트레이에서 복원’ 버튼을 눌러야만 나타나게 만들면 안 된다.
- 일반 창이 열린 앱에 트레이 아이콘도 함께 있다고 해서 독에서 제외하지 않는다.
- 앱 복원 때 기존 창을 다시 사용하고 중복 창을 만들지 않는다.
- 실제 제품에 모든 앱을 강제로 트레이에 넣는 기능을 요구한 것은 아니다. 미리보기 상단의 ‘트레이로 보내기’는 상태 확인을 위한 시험 버튼이다.

## 6. 표시 방식·모니터·작업공간

- 독 설정에서 항상 표시/자동 숨김을 선택한다.
- 자동 숨김이면 고정된 화면 끝으로 마우스를 가져왔을 때 나타난다. 기본은 아래이며 위·좌·우로 옮길 수 있다.
- 독은 기본적으로 주 모니터 하나에만 표시한다. 선택한 다른 모니터로 이동 가능하다.
- 손잡이를 끌어 놓으면 가까운 화면 끝에 붙는다. 화면 중간의 임의 위치에 멈추지 않는다.
- 좌우 배치 시 세로 독이 되고 AI 패널은 안쪽으로 펼쳐진다.
- 모니터 분리·해상도·배율 변경 때 독이 화면 밖에 남지 않도록 복구한다.
- 작업공간별로 창을 구분한다. 현재 공간에서 앱을 열었다고 주 작업공간으로 강제 이동하지 않는다.
- 전체 창 보기는 현재 작업공간의 창을 표시하고 최소화된 창도 선택해서 복원할 수 있다. 빈 공간에는 안내를 표시한다.
- 미리보기의 ‘데스크톱/집중 공간’ 두 개는 예시다. 실제 Windows 가상 데스크톱 연동 방식과 지원 범위는 아직 결정하지 않았다. 임의의 가짜 공간으로 실제 기능을 대체하고 완료라고 하지 않는다.

## 7. AI — 사용자가 채택한 최종 흐름

### 제품 동작

- **독 안에서 바로 대화**한다. 단순히 외부 AI 앱 창으로 돌아가는 버튼만 제공하는 v11 방식은 최종안이 아니다.
- ChatGPT, Claude 등 사용자가 사용하는 서비스를 추가하고 선택한다. 기본 제공 AI는 없다.
- 이미 결제 중인 월정액 구독을 쓰고 싶어 한다. **별도 API 키 입력이나 추가 API 과금 방식으로 임의 변경하지 않는다.**
- 기본은 사용자가 선택한 **기존 서비스의 실제 기존 대화를 이어 쓰는 것**이다. 같은 모델을 새로 호출해 비슷한 대화를 만드는 것으로 대체하지 않는다.
- 매 메시지·독 재개방마다 새 대화를 만들지 않는다. 같은 대화 식별자를 유지한다.
- 사용자가 ‘새 대화’를 명시적으로 선택하면 새 대화 작성으로 전환할 수 있다. 빈 새 대화에서 버튼을 반복해 눌러 빈 대화 목록을 늘리지 않는다.
- 기존 대화를 다시 선택할 수 있고, 서비스별 선택한 대화와 미전송 초안을 분리한다. 독을 접었다 펴도 선택과 초안을 유지한다.
- 실제 서비스와 연결한 프로그램에서는 마지막 선택 대화, 앱 설정 등 필요한 상태를 재시작 후에도 보존한다. 로그인 비밀정보와 일반 설정을 구분해 저장한다.
- 수정본 12 이후의 AI 선택·대화 선택·새 대화·입력창 구성을 사용자가 명시적으로 채택했다. 이 구조를 기준으로 제작한다.

### 현재 구현과 검증되지 않은 사항

- 지금은 로컬 UI 체험이다. 앱 등록은 이름 등록일 뿐 계정 로그인이 아니다.
- ‘기존 대화 · 연결 대기’는 자리표시자다. 실제 ChatGPT/Claude 대화 ID·본문을 불러온 적이 없다.
- 입력한 메시지는 미전송으로만 쌓이며 실제 AI 응답을 생성하지 않는다. 현재 페이지를 종료하면 해당 임시 대화·초안은 사라진다.
- **구독 로그인 권한이 있다고 기존 대화 기록 접근·독 내부 전송 권한까지 생긴다고 가정하면 안 된다.** 서비스별 공식 지원을 검토해야 한다.
- 개발 첫 단계에서 인증·기존 대화 조회·동일 대화에 전송·신규 대화 생성·독 내부 표시가 각각 가능한지 검증한다. 가능/불가/미확인을 나누어 보고한다.
- 계정 세션 복사, 토큰 추출, 쿠키 가져오기, 비공식 비공개 기능 호출을 기본 해결책으로 사용하지 않는다. 로그인은 해당 서비스가 허용하는 사용자 로그인 흐름으로 처리한다.
- 목표 방식이 제공되지 않으면 가짜 연동이나 API 전환으로 완료 처리하지 않는다. 독 디자인 작업은 진행하되 실제 연동 제약과 선택 가능한 대안을 구체적으로 제시하고, 사용자 동의 없이 제품 흐름을 바꾸지 않는다.

## 8. 성능과 실제 프로그램의 완료 기준

- 사용자 우려: 모든 프로그램과 미리보기를 계속 돌리면 부담이 커지지 않는가. 이 우려를 반영해 숨겨진 독·AI 패널·미리보기를 불필요하게 반복 렌더링하지 않는다.
- 일반 창 목록과 활성화·최소화·닫힘·표시 변화에 반응하고, 실제 OS 상태를 기준으로 동기화한다. 미리보기처럼 버튼 플래그 하나에만 의존하지 않는다.
- 기본 권한으로 가능한 범위를 우선 구현하고 별도 권한이 필요한 앱은 상태를 정확히 표시한다.
- 프로그램이 종료되거나 실패해도 Windows 작업 표시줄·트레이·기본 창 조작을 계속 사용할 수 있어야 한다.
- 재시작 시 고정 앱·순서·위치·표시 모드·AI 선택 등 설정이 유지되어야 한다.
- 실제 창을 최소화·복원하는 것과 그 창에 macOS 같은 모션을 적용하는 것은 별도 검증 대상으로 다룬다.

## 9. 구현 단계 제안 — 미확정 기술 스택과 구분

아래는 인계용 개발 순서이며, 사용자가 특정 프레임워크를 선택한 것은 아니다.

1. 환경과 파일을 확인하고 native Windows 프로젝트를 만든다. AI 목표 연동의 공식 지원 가능성은 초기에 별도로 확인한다.
2. 실행 가능한 반투명 독을 띄우고 실제 일반 창을 열거·그룹화·활성화·최소화·복원한다. Windows 표시줄은 유지한다.
3. 고정·순서·자동 숨김·가장자리·모니터·설정 저장을 연결한다.
4. 트레이 전용/최소화 구분과 독 외부 복원 감지를 구현한다.
5. 실제 미리보기·전체 창 보기·작업공간 동작과 모션을 붙인다.
6. 검증된 방법으로만 AI 로그인·기존 대화 연결을 구현한다. 미지원 부분은 상태를 명확히 보이고 남겨 둔다.
7. 실제 앱으로 기능·성능·복구를 검증하고 실행 방법 및 빌드 산출물을 제공한다.

## 11. 자료 안내와 과거 오류

- `START-HERE.html`: 최신 독립 미리보기. 자료 묶음을 풀고 브라우저로 열면 된다.
- `project/mac-motion-preview.html`: 편집 원본. `project/dock-runtime.js`: 동작 코드. 같은 코드가 HTML 안에도 들어 있으므로 수정 시 맞춰야 한다.
- `project/subscription-panel.html`, `project/subscription-ai.js`, `project/dock-chat-v12.js`, `project/dock-chat-v12.css`: 현재 AI 화면과 코드. 파일명 v12여도 이후 채택한 디자인의 원본으로 남아 있다.
- `project/verify-tray-v14.cjs`: 트레이 복원 누락 재현/수정 검증. `project/verify-chat-v13.cjs`: 채팅 흐름·전체 아이콘·한 줄 배치 등. 테스트 경로는 원래 컴퓨터 전용이므로 옮긴 환경에 맞춘다.
- `references/`: 사용자 첨부 스크린샷. `대화원문.html`/`.md`: 공개 메시지 기록. 원문에는 폐기된 제안과 나중에 수정한 설명도 있으므로 본 문서를 우선한다.
- 옛 v10 API 설정, v11 외부 앱 바로가기 전용 화면, 앱 페이지 넘김·두 줄 배치는 참고 이력일 뿐 최종안이 아니다.
- 과거 버그: 아이콘 DOM 재생성 때문에 클릭이 사라짐, 클릭에도 드래그 포인터를 잡음, 다른 공간에 적용된 전역 창 개수 제한, 전체 창 선택 무반응, 복원 후 trayOnly 플래그 잔존. 같은 문제가 native 구현에 재발하지 않도록 실제 OS 상태와 입력 이벤트를 검증한다.
- 미리보기의 공간당 12개 제한, 가짜 앱 5종, 시계 고정값, 상단 시험 버튼은 제품 요구가 아니다.

## 12. 대화와 자료의 이동

사용자는 이 대화에서 **‘이사 백업해줘’**를 말하면 그 시점까지의 공개 대화 원문, 최신 코드·미리보기, 참고 이미지, 최신 인계 문서를 ZIP으로 묶고 검증해 링크를 받기로 했다. 다른 대화에서 자동으로 이 약속을 기억한다고 가정하지 말고, 이 문서를 읽은 이후 명시적인 요청으로 처리한다.

ZIP은 파일 백업이다. 기존 앱 대화 목록, 로그인 상태, 구독 자격증명, 설치된 개발 도구, 실행 중인 OS 상태를 복원하지 않는다. 원문은 추출 시점까지만 포함한다.
