## 실제 독의 유리 배경

Windows 11에서는 네이티브 Desktop Acrylic을 뒤 화면에 적용하고, 얇은 WPF 장식 레이어로 유리 테두리와 부분 반사광을 그립니다. 재질 수치와 그라데이션은 `src/Dock/GlassTheme.cs`에서 조정합니다. WPF 장식은 클릭/드래그를 가로채지 않고 기존 아이콘 위에 표시되지 않습니다.
## 독 표면 스타일

독은 완전 투명 대신 푸른 기가 도는 반투명 유리 표면, 얇은 하이라이트 테두리, 상단 반사광과 부드러운 그림자를 표시합니다.
## AI 바로가기 동작

AI 아이콘을 누르면 선택한 ChatGPT 또는 Claude 앱이 Windows 시작 메뉴에 등록된 앱 항목으로 실행됩니다. 아이콘을 우클릭하면 대상을 바꾸거나 사용자 지정 Windows `.exe`를 지정할 수 있습니다. 앱이 설치되지 않은 경우 웹으로 대신 열지 않고 안내합니다. 기존 AI 서비스의 로그인과 대화 기록은 해당 앱이 관리합니다. GlassDock은 대화 내용을 읽거나 보내지 않으며, 자체 AI 채팅 패널과 API 연동은 제공하지 않습니다.
# GlassDock 0.2 — 승인 화면 UI 수정 빌드

현재 소스 버전은 **0.2.1**이다. [사용자 PC 로컬 검토 및 검증 기록](docs/LOCAL_VALIDATION_20261105_KO.md)에 Windows 빌드·테스트·publish 결과와 최신 작업 방식을 기록했다. 이후 수정은 이 프로젝트 소스에 직접 적용한다. 아래 클라우드·ZIP 설명은 이전 배포 이력이다.

0.2는 사용자가 올린 사진 2를 기준으로 AI 패널과 아이콘을 재구현한 버전이다. [화면 변경 내역](docs/UI_V02_KO.md)과 업데이트 ZIP의 읽어주세요.txt를 우선 참고한다. 이전 0.1의 Windows 실행은 사용자가 확인했으며, 이번 0.2의 실제 화면 검증은 아직 필요하다.

요구 기준은 첨부 CODEX_IMPLEMENTATION_BRIEF_KO.md → 승인 v14 START-HERE.html이다. 첨부 문서의 요청 범위만 구현 기준으로 삼았으며 기존 HTML을 Windows 프로그램으로 포장한 것이 아니다. 기존 작업 폴더와 별개인 /workspace/windows-dock에서 새 C# 프로젝트를 만들었다.

## 실행

Windows 10/11 **x64**에서 ZIP 전체를 풀고 `GlassDock.exe`를 실행한다. .NET 런타임을 포함한 빌드로 별도 .NET 설치가 필요 없다. 설치·관리자 권한·서버·API 키는 필요 없다. 서명하지 않은 개인 개발 빌드이며 배포용 설치 프로그램은 없다. 이 빌드는 Linux에서 교차 컴파일했으며 Windows 실행 검증 전이다.

- 독 손잡이 `⠿` 오른쪽 클릭: 위치, 모니터, 자동 숨김, 프로그램 고정, 종료.
- 손잡이 끌기: 놓은 모니터에서 가까운 가장자리로 붙는다.
- 앱 아이콘 클릭: 현재 공간의 실제 창을 선택/최소화/복원한다.
- 앱 오른쪽 클릭: 실제 창 미리보기, 고정/해제, 새 창 실행 요청, 정상 닫기 요청.
- 아이콘 끌어 다른 아이콘에 놓기: 순서 변경 및 고정.
- `▦`: 현재 공간의 전체 창 목록 및 DWM 썸네일 선택.
- `▱`: Windows 기본 작업 보기 호출을 통한 작업공간 전환. 자체 가상 공간이나 비공개 데스크톱 전환 API를 쓰지 않는다. 이 Shell 호출은 Windows 버전별 현장 검증이 필요하다. 기본 Win+Tab 단축키는 그대로 유지된다.
- `✧`: 독 안 AI 패널. 서비스 등록은 이름 등록이며 로그인이나 계정 연결이 아니다.
- 종료: 손잡이 설정 메뉴 또는 Windows 트레이의 GlassDock 메뉴.

Windows 작업 표시줄과 트레이는 숨기거나 수정하지 않는다. 독은 선택 모니터의 Windows 작업영역 안쪽에 배치한다. 설정은 `%LOCALAPPDATA%\GlassDock\settings.json`, 오류는 같은 폴더의 `errors.log`에 저장한다. AI 초안은 **로컬 평문**이며 서비스별로 분리된다. 이 파일에는 로그인 비밀정보를 저장하지 않는다. 원상복구는 독을 종료하면 되며, 설정을 초기화하려면 종료 후 해당 설정 파일을 삭제한다. 자동 시작 등록은 하지 않는다.

## 구현한 코드

- 픽셀 투명 WPF 둥근 독 셸, 한 줄/한 열 배치, 기본 480ms 독 페이드 모션. 평소에는 배경 없이 아이콘을 표시하고 AI 패널을 열었을 때만 흰 배경을 표시한다.
- EnumWindows로 일반 창 자동 감지, 실행 경로별 그룹, 실행 점·창 개수.
- WinEvent 표시/숨김/닫힘/전경 이벤트를 140ms로 합쳐 갱신하고 3초 복구 확인을 수행한다. 최소화는 표시 창으로 유지하며 숨겨진 트레이 전용 상태와 구분한다. 트레이 외부 복원도 OS 목록 갱신으로 감지한다.
- 현재 가상 데스크톱 확인은 공식 IVirtualDesktopManager. 확인할 수 없는 창은 조작 대상에서 제외한다.
- 한 창 최소화 → 연속 재클릭 시 전체 최소화 → 전체 최소화 상태에서 전체 복원. 4초 이내를 연속 클릭으로 처리하는 첫 구현값이다. 다른 앱 선택/전체 창 선택 등에서 임시 상태를 정리한다.
- 미리보기는 실제 DWM 썸네일이며 열려 있는 미리보기 창에서만 등록한다. 미리보기 닫기/변경 때 해제한다. 최소화/보호 창은 OS의 마지막 프레임 또는 빈 화면일 수 있음을 표시한다.
- 고정·순서·가장자리·모니터·표시 모드·서비스 선택·서비스별 미전송 초안 저장.
- 독 자동 숨김 때 마우스 입력을 통과시키고 선택 작업영역 끝에서 다시 나타나도록 위치 확인. 모니터/배율 변경 이벤트 후 재배치.
- 앱 종료는 WM_CLOSE 요청이며 프로세스 강제 종료가 아니다.

## 완료하지 않은 부분

AI는 [공식 지원 검토](docs/AI_FEASIBILITY_KO.md)를 참고한다. **기존 ChatGPT/Claude 대화 연결·로그인·전송은 미구현이며 버튼이 비활성화되어 있다.** API 전송·자동 새 대화·가짜 응답·가짜 기존 대화는 없다. 연결 성공을 검증하지 못했으므로 실제 대화 ID·대화별 초안 저장도 아직 연결하지 않았다.

이 버전은 실행 파일을 제공하는 첫 개발 단계다. 승인 v14와 픽셀 단위 동일한 완성 UI가 아니다. AI 패널은 레이아웃 크기를 반복 변경하지 않는 페이드·확대/축소 모션을 사용한다. 앱 창의 macOS 같은 이동 모션, 커서 호버 미리보기, 독 내 작업공간 직접 선택/이동은 남아 있다. OS 창 애니메이션은 기본 Windows 동작이다. 전체 창 보기는 현재 리스트와 선택한 창의 큰 썸네일 형태이며 v14의 모든 창 타일 화면은 후속 작업이다.

실행 파일 경로 기준 그룹이므로 같은 실행 파일의 서로 다른 앱 ID/UWP ApplicationFrameHost/일부 브라우저 프로필의 구분은 아직 부족하다. 권한 때문에 프로세스 경로를 읽을 수 없는 창은 제외될 수 있다. Windows의 전경 활성화 제한으로 전환이 거부되면 안내한다. 새 창 실행은 일반 실행 요청이며 탐색기나 브라우저 등 앱별 전용 인수는 추후 검증해야 한다.

혼합 DPI/모니터 분리, 트레이 앱별 동작, 가상 데스크톱 이동, 자동 숨김과 기본 표시줄 자동 숨김 조합, 포커스·드래그 경쟁, CPU·메모리·입력 지연은 실제 Windows에서 미검증이다. 숨겨진 비고정 앱과 권한 제한 프로세스는 완전히 분류할 수 없으므로 범용 트레이 감지를 보장하지 않는다. 극단적인 아이콘 수 초과는 측정값을 도구 설명에 표시하고, 페이지·두 줄·자동 축소 정책은 추가하지 않았다. 초과 시 일부 아이콘이 화면 밖으로 나갈 수 있어 정책 결정이 필요하다.

## 개발·검증

.NET 8 SDK에서 `./build.ps1`을 실행하면 클릭 정책 테스트 후 `artifacts/win-x64`에 독립 실행 빌드를 만든다.

```powershell
dotnet run --project tests/PolicyTests.csproj -c Release
dotnet build src/Dock/Dock.csproj -c Release
dotnet publish src/Dock/Dock.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/win-x64
```

검증 결과와 실기기 절차는 [WINDOWS_VALIDATION_KO.md](docs/WINDOWS_VALIDATION_KO.md)에 있다. Linux 테스트 통과는 Windows Win32/COM/DWM 통합 테스트 통과를 의미하지 않는다.
