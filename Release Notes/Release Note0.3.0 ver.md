# Release Note0.3.0 ver

대상: GitHub에 업로드된 GlassDock 독 실행본과 소스. 개발·검증·이 노트 작성: 2026-11-11, 한국 시간.

제품 버전은 `source/src/Dock/Dock.csproj`의 **0.3.0**입니다. 0.2.1의 기능은 그대로 유지하며, 이번 버전에서 macOS 스타일 지니 최소화 효과를 추가했습니다.

## 현재 적용 상태

- 0.2.1의 유리 독, 실제 앱 아이콘, 호버 미리보기, 전체 창 보기, 휴지통, 앱·도구 구역 배치를 그대로 유지합니다.
- 창을 최소화하면 창이 휘어지며 독으로 빨려 들어가고, 복원할 때는 반대 방향으로 나오는 지니 효과를 추가했습니다.
- 지니 효과의 사용 여부, 들어가는 위치(앱 아이콘 / 독의 창 썸네일), 속도를 독 설정 메뉴에서 고를 수 있습니다.

## 1. 지니 최소화 효과

- **적용 범위:** 독 아이콘 클릭으로 최소화할 때와 각 창 제목 표시줄의 `_` 버튼을 눌렀을 때 모두 적용됩니다. 복원할 때도 반대 방향 지니 효과가 나옵니다.
- **동작 방식:** 최소화 직전에 창을 한 장 캡처하고, 화면 위 투명 오버레이에서 그 이미지를 3D 메시로 휘어 독까지 이동시킵니다. 실시간 미리보기와 달리 `PrintWindow`를 사용하므로 노란 캡처 테두리가 나타나지 않습니다.
- **Windows 기본 애니메이션과 겹침 방지:** 효과가 진행되는 동안 해당 창에만 DWM의 최소화 애니메이션을 끕니다(`DWMWA_TRANSITIONS_FORCEDISABLED`). 이 설정이 안 되는 창은 효과 동안만 창을 투명하게 만드는 방식으로 대신합니다. 효과가 끝나거나 독이 종료되면 원래 상태로 되돌립니다.
- **독 방향:** 독이 위·아래·왼쪽·오른쪽 어디에 있어도 그 방향으로 빨려 들어갑니다. 독이 자동 숨김으로 가려져 있으면 독이 있는 화면 가장자리 가운데로 들어갑니다.
- **`_` 버튼 처리:** 독이 관리하는 앱 창의 최소화 버튼 클릭만 가로채고, 효과를 시작한 뒤 앱에 일반 최소화 요청(`SC_MINIMIZE`)을 보냅니다. 버튼을 누른 채 밖으로 끌어 놓으면 일반 버튼처럼 취소됩니다. 마우스 처리는 별도 스레드에서 실행해 독 화면 갱신이 시스템 마우스를 지연시키지 않게 했습니다.

## 2. 최소화 위치 두 가지와 속도

- **앱 아이콘으로 들어가기 (기본):** 창이 해당 앱의 독 아이콘 속으로 들어가며 마지막에 사라집니다. 독 크기는 변하지 않습니다.
- **독에 창 썸네일로 남기:** 휴지통 옆에 칸이 새로 생기고 창이 작은 썸네일로 남습니다. 최소화된 창마다 칸이 생기며, 썸네일을 클릭하면 그 창이 복원됩니다. 썸네일 구석에는 앱 아이콘이 함께 표시됩니다.
- **속도:** 아주 느리게(0.5배), 느리게(0.75배), 기본(macOS와 같은 약 0.5초), 빠르게(1.5배), 아주 빠르게(2배) 중에서 고릅니다.
- **설정 위치:** 독 손잡이 `⠿` 오른쪽 클릭 → **최소화 효과 (지니)**. 설정은 `settings.json`의 `GenieEnabled`, `GenieMode`, `GenieSpeed`에 저장되며, 기존 설정 파일에 값이 없으면 기본값(켜짐, 앱 아이콘, 1배)으로 시작합니다.
- 두 위치 방식은 결정 전에 대화 안의 인터랙티브 미리보기로 비교한 뒤 둘 다 넣고 선택하는 방식으로 정했습니다.

## 3. 클릭 통과 수정

- 독과 미리보기 카드의 네이티브 유리 배경 창이 그 아래에 있는 **다른 프로그램의 클릭을 막던 문제**를 수정했습니다. 기존 방식(`HTTRANSPARENT`)은 같은 프로그램 안의 창에만 클릭을 넘겨서, 유리 영역이나 그림자 영역 아래의 다른 앱 버튼이 눌리지 않을 수 있었습니다.
- 유리 배경 창을 `WS_EX_LAYERED | WS_EX_TRANSPARENT`로 만들어 모든 창에 클릭이 통과하도록 바꿨습니다. 수정 후 독과 미리보기 카드의 유리 외형이 이전과 같은 것을 화면 캡처로 확인했습니다.
- 이 문제는 지니 효과 테스트 중, 호버 미리보기가 열린 직후 근처 창의 `_` 버튼 클릭이 사라지는 현상으로 발견했습니다.

## 당시 검증 기록

| 단계 | 기록된 결과 | 범위·제한 |
|---|---|---|
| 단위 테스트 | 클릭 정책 15개, 배치·비율 30개, 앱·도구 순서 18개, 지니 곡선 17개 | 지니 곡선은 네 방향 독에서 시작·끝 위치, 행 겹침 없음, 텍스처 좌표, 페이드 확인 |
| 실제 실행 자동 테스트 | 두 방식 모두 `_` 버튼 최소화 → 독 클릭 복원 → 독 아이콘 최소화 통과 | Windows 문자표 창으로 실행. 호버 미리보기가 열린 상태에서의 `_` 클릭 포함 |
| 화면 확인 | 최소화·복원 중간 장면에서 창이 휘어 독으로 이동하는 모습 캡처 | 위쪽 독 기준으로 확인. 다른 방향은 단위 테스트로 확인 |
| 상태 복원 | 효과 후 투명하게 남거나 애니메이션이 꺼진 채 남은 창 없음, 오류 기록 없음 | 테스트 창 기준 |
| 배포본 | Release / win-x64 / self-contained 게시 성공, ZIP 내부 EXE와 원본 SHA-256 일치 | 다른 PC에서의 실행은 확인하지 않음 |

테스트 중 사용자가 같은 PC에서 마우스를 쓰던 회차는 다른 창이 앞으로 와서 클릭이 빗나갔고, 기능 오류가 아닌 테스트 간섭으로 판단해 결과에서 구분했습니다. 모든 앱·물리 DPI·다중 모니터 조합을 검증한 것은 아닙니다.

## 보류·지원 한계

- `Win+↓` 단축키나 작업 표시줄로 최소화한 창은 Windows 기본 애니메이션을 사용합니다.
- 독을 켜기 전에 이미 최소화돼 있던 창은 캡처 이미지가 없어 효과 없이 복원됩니다. 썸네일 방식에서는 해당 칸에 앱 아이콘을 대신 표시합니다.
- 관리자 권한으로 실행된 창, 응답하지 않는 창, 캡처가 검게 나오는 창은 효과 없이 일반 최소화를 사용합니다.
- 지니 효과가 진행 중인 창은 효과가 끝날 때까지(기본 약 0.5초) 독에서 추가 조작을 받지 않습니다.
