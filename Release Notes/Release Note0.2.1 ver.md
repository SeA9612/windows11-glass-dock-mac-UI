# Release Note0.2.1 ver

대상: 현재 GitHub에 업로드된 GlassDock 독 실행본과 소스. 개발 기록: 2026-11-05 및 11-06 정리본. GitHub 최초 업로드·이 노트 작성: 2026-11-09, 한국 시간.

제품 버전은 `source/src/Dock/Dock.csproj`의 **0.2.1**입니다. 아래 수정들은 이 버전 안에서 누적됐으며, 개별 항목에 새 제품 버전이나 Git 태그를 부여하지 않았습니다.

## 현재 적용 상태

- Windows 11 x64용 런타임 포함 독. 32 DIP 실제 프로그램 아이콘, 기본 두께 52 DIP, 앱 추가 시 길이 40 DIP 증가.
- 뒤 화면이 비치는 유리 재질, 얇은 경계·부분 반사광·안쪽 음영·부드러운 그림자. 아이콘과 글자는 선명하게 유지.
- 고정·실행 앱 표시, 안정적인 순서 저장, 전체 창 보기·Windows 작업 보기, 자동 숨김·가장자리 배치.
- 마우스 호버 실시간 미리보기, 16 DIP 둥근 카드와 독과 같은 유리 배경.
- 앱과 도구 구역 사이를 넘나드는 앱 배치, 고정된 마지막 Windows 휴지통 구역.
- 전용 AI 채팅·바로가기 버튼은 제거. AI 앱은 다른 프로그램과 동일하게 직접 고정해 사용.

## 1. 전체 창 선택과 실행 진단

- 제목 표시줄이 있는 진단용 목록 화면을, 선택 모니터 작업영역을 채우는 제목 표시줄 없는 카드형 선택 화면으로 수정했습니다. 현재 공간의 창마다 실제 DWM 썸네일을 표시합니다.
- 카드 영상과 제목 모두 선택 가능하게 하고, 선택 화면의 포커스 처리가 끝난 뒤 원본 창을 활성화하도록 수정했습니다.
- 최소화 창 복원 요청 후 상태를 확인하고 활성화합니다. 닫혔거나 다른 공간으로 이동한 창은 조작하지 않으며, Windows의 전경 전환 제한을 우회하지 않습니다.
- Esc·빈 배경·닫기 버튼 취소, Tab/Enter 선택, 중복 선택 창 방지, 닫을 때 썸네일·타이머 해제를 적용했습니다.
- 실행 후 화면에 독이 없다는 보고에 따라 시작 진단을 추가했습니다. Debug 실행본의 .NET 런타임 오류와 런타임 포함 배포본을 구분하고, 중복 실행 시 안내하도록 수정했습니다.
- 로컬 검토에서는 테스트 집계 표시를 수정하고 클릭 정책 15개·배치/비율 30개 통과와 Release 빌드 경고 0·오류 0을 기록했습니다.

## 2. 아이콘 순서와 AI 방식 정리

- 앱 선택 때 전경 창의 OS 열거 순서를 따라 독 아이콘이 이동하던 문제를 수정했습니다. 최초 발견 순서와 사용자의 드래그 순서를 저장하고 새로 고침 시 유지합니다.
- 당시 AI 패널의 흰 배경과 모션을 조정했지만, 사용자가 기존 대화 연결만 원함을 확인한 뒤 미연결 기능을 완료로 표시하지 않았습니다.
- 이후 전용 AI 영역을 바로가기 방식으로 바꾸고, 웹 대신 Windows 설치 앱 실행으로 변경했습니다. 마지막에는 사용자가 AI 앱을 직접 고정해 쓰기로 하여 전용 AI 버튼·메뉴·앱 검색/실행 코드를 제거했습니다.
- 현재 독에서 AI 로그인·대화 기록 읽기·전송을 제공하지 않습니다. 기존 고정 목록은 보존합니다. 예전 AI 패널의 700/600ms 모션과 바로가기 선택 메뉴는 현재 기능이 아닙니다.

## 3. 실제 유리 배경과 독 이동 모션

- 색상·50% 배경·완전 투명 실험을 거쳐, 실제 뒤 화면을 흐리는 네이티브 재질과 별도의 반사·경계 장식으로 구성했습니다. 테마 값을 `GlassTheme.cs`에 모았습니다.
- WPF 레이어드 창과 DWM 요청의 조합을 재검토하고 네이티브 합성과 DPI에 맞춘 둥근 영역을 적용했습니다. 후속 구현은 `HostBackdrop`과 별도 클릭 통과 배경 창을 사용합니다.
- 장식은 클릭·드래그를 가로채지 않게 하고 아이콘 위에 반사광을 덮지 않도록 구성했습니다.
- 이동 손잡이 선택 영역을 확대하고, 이동 중 한 칸으로 280ms 접힘 → 놓은 가장자리에서 460ms 펼침을 적용했습니다. 이동 중 자동 숨김·아이콘 갱신을 보류하고 배경 크기도 동기화합니다.
- 초기 DWM 요청 성공은 실제 픽셀 검증과 구분했습니다. 뒤의 미리보기·외형 검증에서 실제 테스트 창 캡처를 확인한 기록을 아래에 따로 적었습니다.

## 4. 호버 미리보기와 영상 클립

- 앱 아이콘에 300ms 머무르면 자동 미리보기를 표시하고, 카드로 이동할 수 있도록 닫힘을 250ms 유예합니다. 열려 있는 창이 없는 앱에는 자동 표시하지 않습니다.
- 우클릭으로 호버 미리보기를 켜고 끄며 설정을 저장합니다. 클릭·드래그·이동 중에는 미리보기를 정리합니다.
- 독 방향에서 18 DIP 이동하는 300ms 등장 모션을 추가했습니다. 자동 카드는 화면과 한 줄 제목 중심으로 간결하게 만들고, 최소화 창에만 복원 버튼을 제공합니다.
- DWM 영상이 WPF 둥근 클립 밖에 남는 문제를 해결하기 위해 자동 카드의 영상 경로를 Windows Graphics Capture 연속 프레임으로 변경했습니다. 영상과 제목에 16 DIP 둥근 클립을 적용하며 원본 창 모양은 변경하지 않습니다.
- 보이는 동안 최대 30fps, 한 프레임 처리와 버퍼 재사용을 적용하고 종료 시 캡처 자원을 해제합니다. 최소화·보호·캡처 불가 상태를 안내하고 정적 이미지를 실시간처럼 표시하지 않습니다.
- 불투명 보라 배경과 흰 호버 배경을 제거하고 독과 같은 유리 재질을 적용했습니다. 영상 자체에는 배경 흐림을 적용하지 않습니다. 큰 수동 전체 창 선택 화면은 별도 DWM 경로를 유지합니다.

## 5. 작은 독과 실제 앱 아이콘

- 공통 장식 타일 대신 Windows Shell에서 `.exe`, 지원되는 `.lnk`, AppsFolder/AUMID의 실제 앱 아이콘을 가져옵니다. 고정 앱은 창이 없어도 유지됩니다.
- 32 DIP 아이콘·8 DIP 간격·실행 점·한 줄/한 열 손잡이로 크기를 줄이고, 실제 입력 영역을 독 모양에 맞췄습니다. 그림자는 클릭 통과를 유지합니다.
- 전용 STA 아이콘 추출, DPI별 캐시, 비율·알파 보존과 네이티브 자원 해제를 적용했습니다. 식별 실패는 중립 아이콘으로 표시합니다.
- 영상 처리 중 최신 프레임이 누락되는 문제도 후속 회귀 확인에서 보완했습니다.

## 6. 휴지통과 앱·도구 배치

- 마지막 고정 구역에 실제 Windows 휴지통을 추가했습니다. 빈/찬 상태와 시스템 아이콘을 조회하며 클릭하면 실제 휴지통을 엽니다.
- 비우기는 사용자가 메뉴를 선택했을 때만 요청하고 Windows 확인을 생략하지 않습니다. 앱 드래그로 파일을 삭제하는 기능은 없습니다.
- 앱 경로만 저장하던 순서 모델에서 앱·도구를 함께 표현하는 `LayoutOrder`로 변경하고, 도구 사이와 간격 드롭 및 삽입 표시를 추가했습니다.
- 후속 정정으로 `[앱 구역 | 앱도 배치 가능한 도구 구역 | 휴지통]`의 경계를 복원했습니다. `LayoutVersion=2`로 기존 순서를 보존해 이관합니다. 앱은 경계 양쪽에 둘 수 있지만 경계와 휴지통은 고정됩니다.
- 닫힌 앱 위치와 고정 목록·기존 설정을 유지하며 새로 발견된 앱은 왼쪽 구역에 추가합니다.

## 보류·지원 한계

- Windows 캡처 테두리 숨김은 사용자가 **유리 배경만 먼저 적용**하기로 하여 보류했습니다. 기본 실행본은 해당 권한이나 인증서 설치를 요청하지 않으며 OS 캡처 표시가 남을 수 있습니다.
- 기존 AI 대화 직접 연동, 전용 AI 패널, macOS 전체 시스템 애니메이션 대체는 제공하지 않습니다.
- 최소화·보호된 앱의 영상 제공과 전경 활성화는 Windows·원본 앱의 제한을 따릅니다.
- 많은 아이콘이 작업영역을 넘는 경우의 페이지·두 줄·자동 축소 정책은 추가하지 않았습니다.

## GitHub 배포 정리 — 2026-11-09

실행 중이던 `완성본 ex1`의 독 실행 파일과 대응 소스를 `windows11 glass dock mac UI` 폴더로 정리했습니다. 약 188MB 실행 파일은 약 75MB ZIP으로 제공하며, ZIP 내부 실행 파일과 원본의 SHA-256 일치를 확인했습니다. 개인 설정 백업·실행 로그·서명용 개인 키·옛 중복 배포본은 제외했습니다. 상단 바 실행본은 포함하지 않았습니다. 이 과정에서 제품 기능이나 버전은 변경하지 않았습니다.
